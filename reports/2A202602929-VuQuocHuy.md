## Technical decisions

1. **Use the same chunks for lexical and dense retrieval.** BM25 reads the chunks produced from the standardized corpus, so the two retrieval methods can be compared and fused over the same document IDs. The lexical tokenizer uses whitespace splitting; Vietnamese word segmentation was not evaluated.
2. **Fuse rankings with RRF instead of adding raw scores.** Dense cosine similarity and BM25 scores use different scales. RRF combines rank positions, deduplicates by ID, and retains source metadata. Its output score represents fused rank evidence, not cosine similarity.

## Tests and measured results

- The repository test suite passed: **28 passed** (`pytest -q`). Contract tests cover the BM25 result contract, RRF fusion, and retrieval fallback behavior.
- Offline A/B evaluation used 16 golden questions. Hybrid + RRF scored **0.753** answer-relevance proxy and **0.854** context-recall proxy, compared with **0.732** and **0.810** for dense-only. Its expected-source precision proxy was **0.487**, compared with **0.512** for dense-only. Measured latency was **2.66 s** for hybrid + RRF and **1.04 s** for dense-only across the question set.
- The configured fallback threshold is **0.5474**. Calibration reported balanced accuracy **1.000** on 16 in-domain and 8 fixed out-of-domain queries; this small set does not establish performance on unseen queries.

## Limitations

The evaluation measures are deterministic lexical/source proxies, not semantic judgments. The faithfulness proxy is expected to be high because the evaluator uses an extractive answer baseline. PageIndex code is present, but a live PageIndex request could not be verified because no `PAGEINDEX_API_KEY` was configured at report time.
